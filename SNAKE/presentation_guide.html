SNAKE — Improved Edition

A detailed presentation guide covering mechanics, architecture, and design decisions.

Overview

This is a feature-rich Python Snake game built on top of raylib (via the raylib-python-cffi bindings). It extends the classic Snake concept with multiple food types, power-ups, dynamic obstacles, three game modes, per-mode music, animated sprites, and a parallax background.

The game runs at a fixed 60 FPS. The snake does not move every frame — it moves on a configurable interval, giving the game a deliberate, grid-aligned feel while still allowing smooth UI animations.

Architecture

The project is split into single-responsibility modules. No module imports another game module except game.py, which acts as the coordinator. All shared constants live in settings.py.

Design principle — single source of truth Every magic number (sizes, speeds, durations, colours, spawn rates) lives in settings.py. Tuning gameplay never requires touching logic files.

Main Loop

main.py owns the window and drives the loop. It calls update() then draw() on the Game object every frame. The game object is created before if __name__ == '__main__' so that shutdown() (texture unloading) runs even if the window is never opened. 

while not window_should_close():
    current_game.update()        # logic tick
    begin_drawing()
    current_game.draw()          # render
    end_drawing()

Game.update() and Game.draw() both dispatch on the current screen via a match statement, keeping each screen's logic and rendering isolated.

Screen Manager

ScreenManager is a thin wrapper around a single Screen enum value. It provides transition_to() and is_on() helpers, making state transitions readable and preventing direct enum manipulation scattered across game.py. 

class ScreenManager:
    def transition_to(self, screen: Screen):
        self.current = screen

    def is_on(self, screen: Screen) -> bool:
        return self.current == screen

Snake

Body Representation

The snake is a list of Vector2 positions, one per segment. The head is always body[0]. Segments are 20 × 20 px, matching the grid cell size. 

# Initialise a snake of length 1 starting at (100, 100)
self.body = [Vector2(100 - i * self.size, 100) for i in range(self.length)]

Movement — Frame-Rate Independent Ticking

The snake does not move every frame. A frames_counter increments each frame; the snake only moves when frames_counter % move_interval == 0. move_interval defaults to 5 (moves 12 times per second at 60 FPS) and can be adjusted with [ / ]. 

def update(self):
    self.frames_counter += 1
    if (self.frames_counter % self.move_interval) != 0:
        return False   # no move this frame

    # Shift segments: each takes the position of the one ahead
    for i in range(len(self.body) - 1, 0, -1):
        self.body[i] = Vector2(self.body[i-1].x, self.body[i-1].y)

    self.body[0].x += self.direction.x * self.speed
    self.body[0].y += self.direction.y * self.speed
    return True

The method returns True only when the snake actually moved. game.py skips all collision checks on frames where the snake did not move — avoiding false positives from stale head positions.

Input Guard — Preventing 180° Reversal

allow_move is set to False immediately after any direction key is accepted, and restored to True only after the next actual movement tick. This means only one direction change is registered per move, preventing the snake from reversing into itself by pressing two keys rapidly in one tick.

Growth and Shrinking

When food is eaten, a new segment is appended at the tail's current position before the next move displaces it: 

snake.body.append(Vector2(snake.body[-1].x, snake.body[-1].y))
snake.length += 1

Shrinking (poison food or Shrink power-up) simply pops the last element and decrements length.

Spawning — Collision-Safe Placement

Food spawns on a random grid cell that does not overlap any snake segment or obstacle tile. The occupied set is built fresh on each spawn call, and candidates are retried until a clear cell is found. 

occupied_set = {(s.x, s.y) for s in occupied}
while True:
    candidate = Vector2(
        randint(...) * self.size,
        randint(...) * self.size,
    )
    if (candidate.x, candidate.y) not in occupied_set:
        return candidate

Poison Lifespan

Poison food has a 300-frame (5 second) lifespan. A life_timer counts up each frame; when it reaches FOOD_POISON_LIFESPAN the food re-randomises its type and respawns without awarding any score. A shrinking white bar drawn above the tile shows the remaining time visually.

Moving Food

Moving food has a velocity vector with a random horizontal/vertical sign. Each frame its position is offset by the velocity, and when it hits a wall it reflects the appropriate component — classic billiard-ball bouncing.

Collision Detection

Collision is an axis-aligned bounding box (AABB) test between the snake head and the food tile. Because both are grid-aligned squares of the same size, this is equivalent to a single grid-cell equality check but written as a full AABB to handle the Moving food, which moves in sub-grid pixel increments.

Animated Sprites

The Poison food tile can display an animated spritesheet instead of a plain coloured rectangle. The sprite is loaded once in startup() and assigned via food.set_sprites(). If no sprite is registered for a type, the fallback coloured rectangle with a letter label is drawn.

Power-ups

Class Hierarchy

Power-up effects share a common Powerup base class that handles timer tracking and expiry. Subclasses only need to override apply() and, if needed, remove(). 

class Powerup:
    def apply(self, snake):  pass   # called on pickup
    def remove(self, snake): pass   # called on expiry

    def update(self, snake) -> bool:
        self.timer += 1
        if self.timer >= self.duration:
            self.remove(snake)
            return True   # expired
        return False

Pickup Spawning

PowerupManager maintains a single pickup on the field. After the pickup is collected (or at game start), a frame counter begins. Once it reaches POWERUP_SPAWN_INTERVAL (300 frames ≈ 5 s), a new PowerupPickup of a random type appears. Pickups are visually distinguished from food by a white border.

Active Effect Display

Effects with a duration greater than 1 frame are pushed into snake.active_powerups. Each frame, the manager calls p.update(snake) on every active effect and removes those that return True (expired). The UI renders the effect name and a shrinking duration bar in the header — clearly separated from the play field to avoid confusion with collectible items.

Design choice — instant vs. timed effects Shrink's duration is set to 1. The manager checks if effect.duration > 1 before tracking it, so instant effects apply and disappear in the same frame without cluttering the active-effects list.

Obstacles

Brown wall segments spawn progressively as the player scores, making the board increasingly dangerous over time. ObstacleManager tracks the last score at which an obstacle spawned and triggers a new one whenever the score has advanced by spawn_every points. 

while (score - self._last_score >= self._spawn_every
       and len(self.obstacles) < OBSTACLE_MAX):
    self._last_score += self._spawn_every
    self._spawn(snake, food)

The while loop (rather than if) handles the edge case where two score thresholds are crossed in a single tick — for example, eating golden food (+3) when only 1 point away from the next spawn.

Safe Spawning

Obstacles spawn on a random cell that is not occupied by the snake body, food, or any existing obstacle. Up to 200 candidates are tried; if none are found the spawn is silently skipped to prevent an infinite loop on a nearly-full board.

Scoring & Feedback

Score Delta Pattern

food.update() returns a score delta — the change in score caused by that food interaction. Returning a value instead of mutating the score directly keeps Food decoupled from Game. The game applies the delta and enforces the score floor: 

score_delta = self.food.update(self.snake, obs_positions)
if score_delta != 0:
    self.score = max(0, self.score + score_delta)

Score Popups

When food is eaten, a floating label (+1, +3, -1, etc.) is spawned at the food's position. It rises upward and fades out over FOOD_POP_DURATION frames (20). Green for positive deltas, red for negative. This gives immediate, spatially-grounded feedback without interrupting gameplay. 

# Each pop entry: [position, color, timer, score_delta]
self._food_pops.append([eaten_pos, eaten_color, 0, score_delta])

Score Enlargement

For SCORE_POP_DURATION frames after an eat event, the score text in the header scales from 18 px up to 26 px and shifts from white toward orange — a subtle but clear visual pulse that reinforces the feedback.

High Score Persistence

The high score is written to data/highscore.json whenever a new record is set. It is loaded once at startup so it persists across sessions.

Event Logging

Every meaningful game event (mode start, food eaten, shield absorbed, game over, new high score) is written to data/snake.log via Python's logging module. This enables post-session analysis without affecting gameplay.

UI & HUD

All rendering is delegated to the UI class in ui.py. Game never calls raylib drawing functions directly — it passes data to UI methods. This keeps presentation logic out of game logic.

Header Bar

A 40 px strip at the top of the window is reserved for the HUD. The play area begins at y = HEADER_HEIGHT. The header contains:

  • Score — pulses on eat events
  • Best — always visible high score
  • Mode / Timer — shown for Time Attack and Survival
  • Active power-up — name + shrinking duration bar
  • Controls reminder — right-aligned key hint
Why the power-up indicator is in the header The original design placed active power-up icons on the right edge of the play field. This was confusing — players could mistake the status icons for collectible pickups. Moving them into the header (a clearly non-playable UI zone) removes that ambiguity entirely.

Food Pop Animation

draw_food_pops() renders two things per eaten food:

  • An expanding coloured square at the eaten position that grows and fades over 20 frames.
  • A floating score label that rises upward while fading, coloured green or red based on the sign of the delta.

Overlay Screens

Pause, Game Over, and Instructions are semi-transparent overlay boxes drawn on top of the game world. The game world (snake, food, obstacles) is still rendered beneath them for visual context.

Sound Effects

Each food type has its own eat sound (hit-01 through hit-04), played immediately on collision via audio_mgr.play_hit(eaten_type).

Load / unload lifecycle Audio resources are loaded in startup() after the raylib window (and thus OpenGL context) is initialised, and unloaded in shutdown() after the main loop exits. This matches raylib's requirement that all resource operations occur within the window's lifetime.

The background is a procedurally generated set of layered rectangles, simulating a depth effect. Three layers are defined with different colours, densities, and size ranges — far, mid, and near.

Sprite Animation

SpriteAnimator wraps a single-row spritesheet texture. It advances through frames at a configurable FPS by updating a Rectangle source region each tick. 

def draw(self, position, size):
    dest = Rectangle(position.x, position.y, size, size)
    draw_texture_pro(self._texture, self._frame_rec, dest,
                     Vector2(0, 0), 0.0, WHITE)

Using draw_texture_pro allows the sprite to be scaled to exactly the food tile size (FOOD_SIZE) regardless of the original texture dimensions. Currently the Poison food and obstacle tiles use animated sprites; other food types fall back to coloured rectangles.

Key Design Choices

Grid Alignment via Pixel Math

Rather than maintaining a logical grid array, positions are stored as raw pixel coordinates that are always multiples of the cell size (20 px). Collision checks are pure coordinate comparisons. This keeps the data model simple while still being grid-correct.

Skip Collisions on Non-Move Frames

Collision checks only run when snake.update() returns True. This is a correctness decision, not just an optimisation — the head's pixel position does not change between move ticks, so checking every frame would produce repeated false positives.

One Food Item at All Times

There is always exactly one food tile on the board. When eaten, it re-randomises its type and respawns in the same frame. This design avoids edge cases around multiple food items and keeps spawning logic simple.

Score Floor at Zero

self.score = max(0, self.score + score_delta) prevents the score from going negative. Poison food can hurt the player but never creates an absurd negative score, which would feel punishing rather than challenging.

Separation of Logic and Rendering

UI is a stateless renderer — it receives data and draws it. It holds no game state. Game holds state and calls UI methods with the values to display. This means UI changes never risk touching game logic.

Debug Mode

Pressing D during gameplay toggles a debug overlay showing FPS, snake head tile coordinates, active powerups, food type, and mode state. G toggles god mode (collision immunity) and F / N force-eat food or spawn a power-up. This lets any mechanic be tested instantly without playing through naturally.

Game Modes

Classic

Standard Snake. Obstacles spawn every 3 points (max 20). There is no time pressure and no speed escalation. The intended entry-level experience.

Time Attack

The player has 60 seconds to score as many points as possible. The countdown is shown in the header and turns red when 10 or fewer seconds remain. The time counter decrements every frame (not per snake tick), so it is independent of the player's chosen speed.

Survival

Speed escalates as the score increases: move_interval = max(1, SNAKE_MOVE_INTERVAL - score // SURVIVAL_SPEED_INTERVAL). This means every 5 points the snake moves one frame faster, approaching the minimum interval of 1 (60 moves per second). Obstacles also spawn every 2 points instead of 3. The mode is designed to always end eventually — the question is how long the player can survive.

Mode initialisation Each mode resets the PowerupManager, ObstacleManager, score, and snake on start. Time Attack sets time_left; Survival sets a faster obstacle spawn rate. Classic uses all defaults.
